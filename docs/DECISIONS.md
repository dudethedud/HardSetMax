# Decisions

| Date | Decision | Why |
|---|---|---|
| 2026-10-22 | Levels stay with bleed; this bot only does activity tracking + VIP | Avoid duplicate level systems |
| 2026-10-22 | 10 VIP slots, 7-day window, daily reshuffle | Carson's choice |
| 2026-10-22 | Swap announcements combined in one message, ping new VIPs only | Carson's format; avoids publicly pinging people who dropped out |
| 2026-10-22 | Crown custom role uses a lounge button + modal, not a slash command | Keeps the "no public commands" rule and gives a proper input form |
| 2026-10-22 | ~~Postgres on Railway (separate service) instead of SQLite in the container~~ (replaced below: Supabase) | Container disk is wiped on redeploy; a separate DB service survives redeploys and has built-in backups |
| 2026-10-22 | TypeScript + discord.js v14 + Prisma | Matches the EDSA project stack |
| 2026-10-22 | VIP polls: 1 per VIP per day, channel locks for that VIP right after their poll, bot pings the Polls role | Carson's rule; locking immediately prevents a second poll instead of punishing after; VIPs can't spam the ping |
| 2026-10-22 | Server-wide cap of 2 polls/day (first come, first served); channel locks for the whole VIP role once hit | 10 VIPs × 1 poll each would mean up to 10 pings a day; Carson chose a server cap |
| 2026-10-22 | Crown always goes to a current VIP (top scorer of the new VIP list) | Avoids a Crown holder without VIP perks |
| 2026-10-22 | Poll discussion happens in a bot-created thread on each poll; everyone can chat in threads only | Keeps #polls clean while letting people discuss |
| 2026-10-22 | Staff can post polls with no limits; their polls get the ping and thread and don't use the VIP cap | Carson's choice |
| 2026-10-22 | Losing VIP is immediate and complete (colour, Crown, custom role, temp voice) through one shared routine; the slot refills at the next reshuffle | Mid-day removals shouldn't leave people with VIP perks until midnight |
| 2026-10-22 | Single-instance lock before connecting to Discord | Railway redeploys can overlap; two connected copies would double-count activity and double-answer buttons |
| 2026-10-22 | One "server-day" boundary (default 00:00 local, DST-aware) used by everything | The old 00:00 day vs 00:05 reset mismatch could unlock polls wrongly |
| 2026-10-22 | Spam filter (repeats, low effort, bursts) + 60 s cooldown instead of a daily message cap | Carson's choice: filter spam, don't cap genuine chatting |
| 2026-10-22 | Voice capped at 240 counted minutes per day | Stops overnight voice farming |
| 2026-10-22 | Threads use their parent channel's weight | Threads are separate channels in Discord and would otherwise dodge ignored channels |
| 2026-10-22 | Pinned time doesn't count toward history badges | Badges should be earned, not given by a pin |
| 2026-10-22 | Bot keeps its own timeout history + audit-log catch-up on startup | Discord only exposes active timeouts |
| 2026-10-22 | `/polls unlock` works even past the daily cap | Otherwise the command does nothing once the cap is hit |
| 2026-10-22 | Fixed tie-breaker order ending in Discord user ID | Preview and real reshuffle must always agree |
| 2026-10-22 | AI chat as "Puppyboy Carter": hyper and friendly, puppy theme as a light touch; main chat only; replies to mentions and to replies | Carson's choices |
| 2026-10-22 | AI shows the asker their exact rank, never anyone else's stats | Carson chose exact rank; others' stats stay private |
| 2026-10-22 | Free AI provider (Groq free plan by default), provider-agnostic, with daily cap and pre-written fallback | Carson wants it free; free tiers have daily limits, so the bot must degrade gracefully |
| 2026-10-22 | AI provider chain: Groq → Cloudflare Workers AI → pre-written replies; one account per provider | More free daily capacity without breaking provider terms. OpenRouter free (50/day) too small; Gemini free uses prompts for training; Cerebras is an expiring trial |
| 2026-10-22 | Per-person AI limit of 3 replies per minute instead of a 30 s cooldown | Allows quick back-and-forth while still stopping spam |
| 2026-10-22 | Invite tracking dropped; VIP is decided by activity only | Owner's choice |
| 2026-10-22 | Commands use `contexts: [Guild]` instead of `dm_permission = false` | Discord deprecated `dm_permission`; `contexts` is its replacement and does the same thing. A test checks every command has it plus `default_member_permissions = Administrator` |
| 2026-10-22 | Prisma pinned to 7.x (7.10.1); the `prisma` CLI is a runtime dependency | npm's "latest" for Prisma was an 8.0 release candidate. `npm start` runs `prisma migrate deploy` in production, so the CLI must be installed there |
| 2026-10-22 | Luxon does the timezone math in the server-day helper | Mature, DST-aware library instead of hand-written date code |
| 2026-10-22 | A server-day is named by the local date it starts on (`YYYY-MM-DD`) | With the default 00:00 boundary the key is just the local calendar date |
| 2026-10-22 | Boundary in the spring-forward gap (e.g. 02:30) runs at the first valid time after the gap (03:00); a boundary in the repeated fall-back hour uses its first occurrence | SPEC §2 says "next valid time"; this keeps every instant in exactly one server-day |
| 2026-10-22 | `gateway-leader` uses `pg_try_advisory_lock(hashtext('gateway-leader'))` on a dedicated `pg` connection; losing that connection shuts the bot down (exit 1, the host restarts it) | Postgres releases the lock when the connection drops, so another copy may connect; the old one must stop |
| 2026-10-22 | Slash commands are registered to the guild on every startup | Restarts keep commands in sync without a manual step; `npm run register-commands` still exists |
| 2026-10-22 | Phase 1 `/config set` keys: `timezone`, `day-boundary`. Changes are written to `AuditLog` | Real spec settings, so the redeploy proof uses real data. The mod-log channel is configured in Phase 4 |
| 2026-10-22 | Hosting: bot on a free **Wispbyte** Node.js server, database on free **Supabase**, instead of Railway | Owner wants it fully free with no card. Railway's free plan is about $1/month of credit; Oracle's free tier needs a credit card; Wispbyte's free plan allows one server, so the database goes on Supabase. Neon's free plan was rejected: the always-open lock connection would use up its 100 compute-hours a month |
| 2026-10-22 | Supabase via the **session pooler** (port 5432), not the transaction pooler | Advisory locks need a session that stays on one connection; the direct connection is IPv6-only |
| 2026-10-22 | Database TLS is always verified: the bot uses Supabase's CA (`DATABASE_CA_CERT`), and migrations run with `sslaccept=strict`. TLS is only skipped for localhost or `sslmode=disable` | The connection carries the DB password and all member data; `sslmode=require` alone accepts any certificate |
| 2026-10-22 | `start.js` is the single entry point (migrate, then start); `npm install` builds via `postinstall`; TypeScript and `@types/*` are runtime dependencies | Wispbyte runs `npm install` and then a JS file, not `npm run build` + `npm start`. The build needs TypeScript even if the host skips dev dependencies |
| 2026-10-22 | Prisma pool capped at 5 connections (`DATABASE_POOL_MAX`) | Supabase's free session pooler allows few connections |
| 2026-10-22 | Backups: nightly GitHub Actions job dumps schema `public` with `pg_dump` (verified TLS), encrypts with `age` for the owner's public key, and keeps 30 days as workflow artifacts. Restores only go into an empty database | Supabase free has no self-service restores. Free and off-site. Encrypting to a public key means neither GitHub nor anyone with repo access can read member data, and the workflow holds no decryption secret. Restoring only into an empty database means a restore can never overwrite live data |
| 2026-10-22 | "Nearly the same" message = at least 80% similar (Dice coefficient over 3-character chunks of the lowercased text with spaces and punctuation removed), configurable as `spam-repeat-similarity` | Owner approved. Only number fingerprints of the chunks are kept in memory, never the text. A one-letter typo in a 20-letter message scores about 0.85 |
| 2026-10-22 | Spam filter order: burst → too short → emoji/sticker only → low effort → repeat → cooldown. Every message counts toward a burst; "filtered" (shown in `/stats`) means flagged by burst, low effort or repeat only | Short, emoji-only and cooldown messages aren't spam, just not counted |
| 2026-10-22 | Until Phase 4 adds eligibility, `/stats` and `/leaderboard` rank all non-bot members: score, then active days, then last-day score, then smaller user ID | Owner approved. Same order as SPEC §4 minus "current VIPs first" |
| 2026-10-22 | `/activity adjust` points belong to today's server-day, so they count once today is in the window | Keeps adjustments on the same day-based window as all other activity |
| 2026-10-22 | Timeouts are keyed by (user, scheduled end). Live: member updates (covers AutoMod). Startup: audit log back to a saved cursor (first scan 30 days), plus members timed out right now | Both the member update and the audit log entry carry the same end time, so the same timeout is never saved twice |
| 2026-10-22 | Voice cap uses today's saved minutes plus unsaved ones; if the database is down when a member's total is first needed, that member's minute is skipped | Never counts past the cap. Totals are loaded once per member per day, so this only matters during an outage |
| 2026-10-22 | Setting a channel's weight back to 1 removes its row | 1 is the default, so only non-default weights are stored |
| 2026-10-22 | To be added as VIP, a member must also have been active within `inactivityDays` (default 3) | Owner approved. Otherwise a high score from early in the week adds someone who is removed for inactivity the next day |
| 2026-10-22 | When pins push VIPs over `slots`, nobody is removed to make room; open slots just aren't filled until the count drops | Owner approved |
| 2026-10-22 | "Held VIP at least `minHoldDays`" is counted in server-days from the day they got VIP to the reshuffle's day | Owner approved; all day logic uses server-days |
| 2026-10-22 | Someone removed in a reshuffle can't be re-added in the same reshuffle | Owner approved |
| 2026-10-22 | Pinned members who aren't VIP yet are added by the reshuffle and take a slot (unless they left or are bots); a pinned VIP is only removed for leaving | SPEC §4 step 4 |
| 2026-10-22 | Announcement pairing: removed VIPs who are no longer ranked (left, ineligible) count as the lowest-ranked | SPEC §4 pairs "lowest-ranked removed VIP" first; unranked is lower than any rank |
| 2026-10-22 | VIP role goes directly above `/config level-roles-top` (bleed's highest level role); if unset, just below the bot's role with a warning | Owner approved. The bot can't tell which roles are bleed's |
| 2026-10-22 | Only one catch-up reshuffle after downtime, for the most recent missed day | Owner approved |
| 2026-10-22 | `/vip pin` on a non-VIP makes them VIP immediately, pinned; `/vip unpin` leaves them VIP for the next reshuffle to decide | Owner approved |
| 2026-10-22 | The VIP role gets all SPEC §3 perms even if @everyone already has some; the bot must have them itself to grant them | Owner approved. Discord only lets a bot grant permissions it has |
| 2026-10-22 | Defaults: VIP colour `#F1C40F`, a timeout within the last 3 days blocks VIP | Owner approved |
| 2026-10-22 | Scheduler checks every 15 s whether the just-closed server-day has a run, instead of a timer to the next boundary | One check covers the normal run, catch-up, clock changes and DST |
| 2026-10-22 | Reshuffle saves VIP changes and its `JobRun` "succeeded" in one transaction; roles, mod-log and announcement come after. | 2026-10-22 | `/vip reshuffle-now` runs as job `reshuffle-manual` keyed by its timestamp, so it doesn't replace the nightly run | SPEC §10: "run the reshuffle immediately" |

| 2026-10-22 | VIP role changed by hand is corrected live (and on startup): added by hand → removed, removed by hand → restored, with a mod-log hint | SPEC §11: the database is the source of truth |
| 2026-10-22 | `CLOCK_OFFSET_MINUTES` (testing only) shifts the clock used for the schedule and reshuffle, not activity counting | PHASES Phase 4 test with a clock override; activity keeps Discord's real timestamps |
